# Week 02 — Python for Real Work + Git/GitHub

**Planned dates:** 19–25 October 2026  
**Status:** Not started

## Goal
Use collections, files, modules, exceptions, and Git to make work reusable and traceable.

## Learning objectives
- [ ] Choose lists, tuples, sets, and dictionaries for suitable tasks.
- [ ] Read and write text/JSON safely.
- [ ] Handle exceptions and split logic into reusable functions/modules.
- [ ] Use Git status, diff, add, commit, log, and push.

## Core concepts
- Lists, tuples, sets, dictionaries
- Text/JSON files and paths
- Exceptions, validation, and modules
- Virtual environments
- Git status/diff/add/commit/log/remotes/push
- GitHub README and meaningful commits

## Daily plan
1. Practice collections and iteration.
2. Read and write text/JSON and understand relative paths.
3. Add validation and controlled exception handling.
4. Refactor into functions/modules and create a virtual environment.
5. Practice Git status/diff/add/commit/log in a test folder.
6. Commit and push the project; inspect it in GitHub’s web UI.
7. Review your commit history and document the fresh-clone run procedure.

## Weekly build
Upgrade Week 1’s game to save score history as JSON, split reusable logic into functions/modules, handle file errors, and publish the project with a clear README.

## Testing and evaluation
- [ ] Missing score-history file is handled or created safely.
- [ ] Malformed/unavailable file errors produce a helpful response.
- [ ] Repeated runs produce readable score history.
- [ ] A fresh clone can follow the README and run the app.

Record the commands actually run and observed output. If a check is manual, record the input and what happened.

- When is a dictionary better than a list?
- What is an exception, and how should it be handled?
- What do git add, commit, and push each do?

Answer these in your own words. Revisit any question you cannot explain without notes.
